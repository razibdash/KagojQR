# Project: KagojQR (Flutter + Supabase)

App name: KagojQR
Package ID: com.kagojqr.app
Viewer URL pattern: https://kagojqr.app/v/<token>

## Goal

Build an MVP mobile app (Flutter) where a vehicle owner uploads personal documents
(driving license, passport, car papers). The app generates a QR code that can be
printed as a sticker and kept in the car. When a traffic officer scans the QR, they
can view the documents in a restricted, short-lived, watermarked viewer. They must
not be able to easily download or share them. The owner must be able to revoke the QR at any time.

## Tech stack

- Flutter (latest stable), Dart null-safety, Riverpod for state management, go_router for navigation
- Supabase: Auth (Google login only), Postgres + RLS, private Storage bucket, Edge Functions (Deno/TypeScript)
- Packages: supabase_flutter, google_sign_in, qr_flutter, mobile_scanner,
  image_picker, file_picker, screenshot (for QR sticker image), share_plus,
  no_screenshot (or flutter_windowmanager for FLAG_SECURE on Android)

## Core principles

1. The QR contains ONLY a random URL token (e.g. https://<domain>/v/<token>), never any document data.
2. Documents live in a PRIVATE Supabase bucket. No public URLs, ever.
3. Documents are only served via signed URLs that expire in 60 seconds, generated by an Edge Function.
4. Every access is logged and the owner is notified.
5. Owner can revoke/regenerate the QR token instantly.
6. Never hardcode secrets. Use .env / Supabase secrets. Never expose the service-role key to the Flutter client.

## Database (Supabase Postgres) - create as SQL migrations

- profiles(id uuid PK -> auth.users, full_name, email, created_at)
  - trigger to auto-create profile on signup
- documents(id, owner_id, doc_type check in ('license','passport','car_paper'),
  file_path, expiry_date, created_at)
- qr_tokens(id, owner_id, token unique (32+ random chars), pin_hash, is_active default true,
  expires_at nullable, created_at)
- access_logs(id, token_id, viewer_name, viewer_police_id, viewer_ip, user_agent,
  doc_type, viewed_at)
- Enable RLS on ALL tables. Owner can only select/insert/update/delete own rows.
  access_logs: owner can only SELECT logs for their own tokens; insert only via Edge Function (service role).
- Storage bucket "documents" (private). Path: {owner_id}/{doc_type}/{filename}.
  Storage policies: owner can upload/read/delete only inside their own {owner_id}/ folder.

## Viewer verification (MVP)

- Owner sets a 4-6 digit PIN when generating the QR (stored hashed, e.g. bcrypt/argon2 in the Edge Function).
- Officer scans QR -> opens viewer -> enters their name + police ID + the PIN the owner tells them.
- Rate limit: max 5 failed attempts per IP+token per 10 minutes, then temporary lock.

## Edge Function: verify-and-view

Input: token, pin, viewer_name, viewer_police_id
Steps:

1. Validate token exists, is_active = true, not expired.
2. Rate-limit check; verify PIN hash.
3. Generate 60-second signed URLs for the owner's documents.
4. Insert row in access_logs (IP, user agent, viewer info, time).
5. Trigger owner notification (start with a DB row/in-app notification; FCM push as a later phase).
6. Return signed URLs + viewer watermark text. Do not return any file paths.

## Secure viewer

- Android: enable FLAG_SECURE on the viewer screen only (blocks screenshots/screen recording).
- Overlay a repeating diagonal watermark: "{viewer_name} | {police_id} | {datetime}".
- Disable long-press/save/share/copy on images. Blur or hide content when app goes to background.
- Auto-close and clear images from memory after 60 seconds, then require re-verification.
- Do not cache images to disk (no persistent cache for these images).
- Web viewer (since officers will not have the app): build a minimal Flutter Web (or simple static HTML+JS) page
  at /v/<token>. Disable right-click and text selection, apply the watermark, and use no-store cache headers.
  NOTE: FLAG_SECURE does not exist on web, so be explicit in the README that this reduces but cannot
  eliminate screenshot or photo risk. Ask me which approach I prefer before building this part.
